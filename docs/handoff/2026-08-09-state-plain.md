# 지금 어디까지 왔나 — 2026-08-09 (쉬운 말 버전)

기술 세부는 옆 문서들에 있습니다. 이건 "무슨 일이 있었고 지금 뭘 믿어도 되는가"만 적은 것입니다.

## 한 줄 요약

ARISTOTLE 코호트가 0명인 원인을 **다섯 개** 찾았고, 그 중 하나를 고쳤습니다.
그리고 **우리가 성능을 재던 방식 자체가 틀렸다**는 걸 알아냈습니다. 그게 이 세션의 제일 큰 결과입니다.

## 0명이었던 이유

| # | 원인 | 상태 |
|---|---|---|
| 1 | 같은 기준을 두 번 넣어서 Circe가 AND로 묶음 | **고침** |
| 2 | CDM에 시술 기록이 아예 0줄 | 미해결 (데이터 부재) |
| 3 | 배제 조건이 너무 넓어 등록 조건을 잡아먹음 | 원인 확정, 코드 수정은 안 함 |
| 4 | 혈소판 수치의 **단위**가 프로토콜과 데이터에서 다름 | 원인 확정, 자동수정은 **불가능**으로 판정 |
| 5 | 개념집합이 그럴듯한데 CDM에서 **0명** | 신규 발견 |

**원인 3과 4를 둘 다 고치면 0명 → 788명**입니다(gold는 1,113명). 하나만 고치면 여전히 0명입니다. 그래서 지난 세션이 "고쳤는데 그대로 0명"이라 실패로 읽었던 겁니다 — 수정은 맞았고, 원인이 하나가 아니었을 뿐입니다.

## 제일 중요한 발견: 채점 방식이 틀렸다

지금까지 "환자 몇 명 나왔나"로 성능을 쟀습니다. 그런데 그 CDM은 **gold 정답에서 자동 생성한 가짜 데이터**입니다. 그러니 환자 수를 재면 파이프라인이 아니라 **데이터 생성기의 관례**를 재는 셈입니다.

가장 선명한 예가 혈소판입니다. 프로토콜은 "10만/mm³ 이하 제외"라 쓰고, gold는 같은 기준을 "100(천 개 단위)"으로 씁니다. 둘 다 맞습니다. 그런데 어디에도 **단위가 적혀 있지 않아서** 컴퓨터는 101과 100,000을 그냥 숫자로 비교하고, 전원을 제외해 버립니다.

그래서 채점을 **개념집합이 gold와 얼마나 겹치는가**로 바꿨습니다. 가짜 데이터와 무관하게 잴 수 있습니다. 규칙은 `AGENTS.md`에 박아뒀습니다.

현재 성적: ARISTOTLE 기준 **recall 0.087 / precision 0.863**. 만든 것은 대체로 맞는데(정밀도 높음), 만들어야 할 걸 많이 빠뜨립니다(재현율 낮음). gold 개념집합 38개 중 9개는 겹침이 아예 0입니다.

## LLM 실험: 해봤고, 결론은 "못 가림"

손으로 만든 단어 목록(`plus`, `as well as` …) 대신 LLM이 의미로 판단하게 바꿔봤습니다. 세 팔을 같은 채점표로 돌렸습니다.

| 팔 | 정확도 | 위험한 실수 | 코호트 붕괴 실수 |
|---|---|---|---|
| 아무것도 안 함 (바닥) | 0.750 | 0 | 7/7 |
| **현행 (단어 세기)** | 0.857 | **0** | 4/7 |
| 로컬 gemma-4B | 0.929 | 2 | **0** |
| gpt-4o | 0.929 | 2 | **0** |

숫자만 보면 LLM이 나아 보이지만 **통계적으로 구분이 안 됩니다**(p=0.69). 문제 수가 28개뿐이고, 그 중 판별력이 있는 건 4개뿐이라 **완벽한 답을 내도 유의해지지 않습니다.** 이건 실험 전에 게이트가 미리 계산해 경고한 내용이고, 실제로 그대로 나왔습니다.

**그래서 배포하지 않았습니다.** 현행 방식이 기본이고, LLM은 환경변수 뒤에 숨겨뒀습니다. 코드와 테스트는 다 있어서 언제든 켤 수 있습니다.

건진 것 두 가지:
- 결함은 **진짜입니다**. 같은 개념집합·같은 그룹인데 `Peripheral occlusive arterial disease`는 걸리고 `Peripheral artery disease`는 안 걸립니다. 어순만으로요.
- **로컬 4B 모델이 gpt-4o와 28개 답이 글자 하나까지 똑같았습니다.** 이 문제엔 유료 모델이 필요 없습니다.

## 왜 실험이 결론을 못 냈나 — 이게 다음 숙제

채점표를 세 번 만들었고 세 번 다 같은 이유로 실패했습니다: **답이 채점 대상이 볼 수 없는 곳에서 나왔습니다.**

1. 철자 유사도로 짝지음 → NYHA "II-III"를 "IV"에 붙임(글자가 비슷해서). 현행 방식의 정답을 오답 처리함.
2. gold의 코드 목록으로 짝지음 → 판정기는 글자만 보는데 답은 코드에서 나옴.
3. gold가 그 기준을 어디에 뒀는지로 판정 → 이건 gold 구조가 강제하는 거라 **못 고칩니다.**

그리고 결정적으로, **필요한 문제 유형이 gold에 0개**입니다. "배제 기준끼리 비교하는 상황"이 실제 파이프라인에선 계속 생기는데, gold 여섯 시험엔 그런 그룹이 하나도 없습니다. 문제를 더 뽑아도 안 나옵니다.

→ **조달 문제지 판정 문제가 아닙니다.** 병원 데이터 단계에 실제 배제 그룹이 있을 테니, 거기가 이 질문의 자연스러운 답일 수 있습니다.

## 지금 믿어도 되는 것 / 아닌 것

**믿어도 됨**
- 0 → 788 계산은 정확합니다(추정이 아니라 비트마스크 산술).
- 원인 3·4·5의 진단과 근거.
- 테스트 705개 전부 통과.
- 로컬 vLLM과 유료 API 중 무엇이 실제로 응답했는지 매 건 기록됩니다.

**믿으면 안 됨**
- 이 가짜 CDM에서 나온 환자 수를 파이프라인 성능으로 읽는 것.
- "LLM이 더 낫다" — 이 실험은 그걸 지지하지 않습니다.
- 값 분포를 보고 단위를 알아낼 수 있다는 기대 — 원리적으로 불가능함을 보였습니다.
