## 1. 무엇을 받았나

요청은 `achilles_results` 원본이었으나, 실제로는 **ATLAS "Data Sources" 화면 export**가 왔다. 세 병원의 형식이 모두 다르다.

| 병원 | 파일 | 형식 | 헤더 |
|------|------|------|------|
| 아주대 | `아주대_아킬레스.xlsx` 1개 | 정규화된 단일 시트 | `domain, concept_id, count` |
| 동아대 | 도메인별 CSV 6개 | 파일명에 도메인 명시 | `Concept Id, Name, Person Count, Prevalence, Records per person` |
| 계명대 | 번호 CSV 5개 | 파일명에 도메인 없음 `(1)~(4)` | `컨셉 아이디, 이름, 환자수, 유병율, 사람 당 기록수` |

형식은 달라도 **의미는 동일**하다: `concept_id` → distinct person count. 오히려 원본 `achilles_results`에 없는 **개념명(Name)과 유병률**까지 포함되어 있다.

## 3. 변환기가 처리하는 이질성

| 문제 | 처리 |
|------|------|
| 파일 형식 3종 (xlsx / 영문 CSV / 한글 CSV) | 헤더 별칭 매칭(`Concept Id`·`컨셉 아이디`, `Person Count`·`환자수`). xlsx는 표준 라이브러리(zipfile+XML)로 파싱해 openpyxl 의존 없음 |
| **`analysis_id` 부재** (ATLAS export가 버림) | 프로브 개념으로 도메인 복원 — 예: `201826`(T2DM)이 있으면 condition, `9202`가 있으면 visit. Ingredient 컬럼이 있으면 drug |
| 계명대 파일명이 번호 | 위 프로브 방식으로 내용 기반 판별 (5개 파일 모두 정상 판별) |
| 인코딩 (UTF-8 / CP949 혼재) | 순차 시도 후 디코드 |
| **한글 파일명이 NFD(자모 분리)** | `unicodedata.normalize("NFC", ...)` 후 매칭. 이걸 안 하면 `'계명대' in name`이 False가 되어 site_key가 깨진다 (macOS 생성 파일에서 재발) |
| 도메인 판별 실패 | 추측하지 않고 경고 출력 후 해당 파일 무시 |

## 4. 알려진 한계 (의도적으로 남긴 것)

### 4-1. `smallCellCount = 0` 으로 설정
현재 세 사이트 모두 0으로 넣었다. **이는 "억제 없음"을 뜻하므로, 실제로 억제가 적용되었다면 해석이 틀어진다** — 누락된 행을 "0명"으로 단정하게 되어 멀쩡한 기준을 제외 제안할 수 있다.

→ 교수님들께 각 사이트의 실제 `smallCellCount` 값을 확인한 뒤 `--small-cell-count`로 다시 생성해야 한다. 확인 전까지는 리포트의 "0명" 판정을 확정으로 읽지 말 것.

### 4-2. `device` 도메인 738행 드롭 (아주대)
우리 계약은 6개 analysis(200/400/600/700/800/1800)이고 device(2100)는 포함하지 않는다. 현재 TTE 코호트가 device 기준을 쓰지 않으므로 드롭이 정상 동작이며, 변환기가 경고로 출력한다. 필요해지면 `DOMAIN_ANALYSIS`에 추가하면 된다.

### 4-3. 아주대 6행 파싱 실패
concept_id가 0이거나 값이 비어 있는 행. 무시해도 무방하나, 변환기가 건수를 출력하므로 급증하면 원본 확인이 필요하다.

## 5. 데이터에서 확인된 사실 (중요)

### 5-1. 약물이 전부 제품(product) 개념 — 성분(ingredient) 개념은 거의 없음

세 병원 모두 약물 상위 개념이 `42918145`, `42919316` 같은 **RxNorm Extension 대역(>40M, 제조사·제형 수준)**이다. 성분 개념(2M 미만 대역)은 병원당 158~371개에 불과하다.

| 조회한 성분 개념 | 아주대 | 동아대 | 계명대 |
|------------------|--------|--------|--------|
| sitagliptin (1580747) | 없음 | 없음 | 없음 |
| linagliptin (40239216) | 없음 | 없음 | 없음 |
| glimepiride (1597756) | 없음 | 없음 | 없음 |
| metformin (1503297) | 없음 | 없음 | 없음 |
| empagliflozin (45774751) | 없음 | 없음 | 없음 |
| warfarin / clopidogrel / apixaban | 없음 | 없음 | 없음 |

**함의**: 코호트를 성분 concept ID로 정의하면 세 병원 모두 **구조적으로 0명**이 나온다. 실제로 그렇게 나왔었다. 성분 → 제품 descendant 확장이 필수이며, 이것이 ADR-030 단계 ①(개념 해석)의 핵심 근거다.

### 5-2. 같은 질환도 병원마다 다른 개념

| 개념 | 아주대 | 동아대 | 계명대 |
|------|--------|--------|--------|
| Essential hypertension (320128) | 1,718,464 | 137,247 | 55,260 |
| Hypertensive disorder (316866) | 없음 | 없음 | 없음 |
| Type 2 diabetes (201826) | 800,323 | 109,292 | 12,802 |
| Atrial fibrillation (313217) | 32,590 | 177 | 10,630 |

상위 개념(316866)이 아니라 하위 개념(320128)으로 코딩된다 → granularity 적응 필요.

### 5-3. Synthea와 정반대인 항목

`Dietary regimen`(4032243)이 세 병원 모두 **존재**한다(아주대 2,574 / 계명대 199 / 동아대 234). Synthea에서는 0이었다. 다만 비율이 0.02% 수준이라 필수 조건으로 쓰면 사실상 전원 탈락 필터로 작동한다.

**함의**: feasibility는 우리 Synthea가 아니라 **각 사이트에서 측정해야 한다**는 ADR-030의 전제가 실제 데이터로 확인되었다.
